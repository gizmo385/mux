- per-host `multiplex = false` opt-out for proxies that can't sustain a `-fN -M` master. Follow-up to the 2026-05-27 verify-after-spawn fix that turned silent degradation into a loud `connect_errors` line: a user whose ProxyCommand can't keep a backgrounded ControlMaster alive (Coder `coder ssh --stdio` gated by a `Match host *.coder !exec "coder connect exists %h"` rule was the original repro) now sees the host fail to connect at startup instead of paying silent per-command SSH cost. A one-shot env-gated byte logger (`MUX_KEYLOG`) captured the actual sequence: an SGR mouse report (`\x1b[<35;49;59M`) was decomposed by `crossterm` into 14 individual `KeyEvent`s with ~10–11 ms inter-byte gaps, and our `handle_terminal_key` faithfully forwarded each byte to the embedded PTY. Claude then received `\e\e\e[<35;49;59M` as keystrokes, leaking literal `[<…M` (or, perceptually, "stray characters / a newline") into the prompt buffer. Subsequent mouse reports in the same burst parsed correctly as `Event::Mouse`, so the failure is the *first* report after a quiescent stretch — likely crossterm's CSI parser timing out between the leading `Esc` and the rest of the sequence when the OS/terminal delivers the bytes slowly. Two candidate fixes:
  - **(1) Filter at the handler boundary.** In `Focus::Terminal`, buffer a bare `Esc` for up to ~30 ms before forwarding. If a `[` follows within the window, hold both. If a parameter byte (`<`, digit, `;`) follows, treat as a misparsed CSI and suppress everything until the terminator (any byte in 0x40–0x7E). Otherwise flush the held bytes and forward normally. Cost: ~30 ms latency on bare-Esc presses; structurally cleaner than a per-byte filter and contained to one module. Lowest risk.
  - **(2) Bypass crossterm's parser for terminal-focus input.** Read raw stdin bytes ourselves while `Focus::Terminal`, split off only the `Ctrl-a Esc` leader chord, pipe everything else straight to the PTY. Worth reaching for if (1) leaves residue.
