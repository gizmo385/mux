# Features

Feature ledger. Grouped by milestone. One line per entry. Plain language.

Legend: ✓ shipped · ⋯ in progress

## Milestone — initial work

### M0 — Local dashboard

- ✓ ratatui app skeleton: header / sessions list / footer, `q` and Ctrl-C to quit
- ✓ local session discovery: scans `~/.claude/projects/`, reads `cwd` from transcript, uses file mtime as last-activity, renders a sortable list with arrow / `j`/`k` navigation
- ✓ live attention state: `notify`-driven transcript watcher derives state from JSONL tail (assistant → needs-input, user/tool result → working), with a 1h idle threshold applied in the UI layer
- ✓ tmux attach: `Enter` switches to the tmux pane whose cwd matches the selected session; `t` opens a new tmux window in that cwd; failures surface in a dashboard status line
- ✓ outside-tmux fallback: when run outside tmux, `Enter` suspends the TUI to run `tmux attach -t <target>` as a foreground subprocess; `t` drops into `$SHELL` in the cwd. TUI resumes when the subprocess exits.
- ✓ resume from transcript: when the selected session has no live tmux pane (e.g. its old window was killed, or there's no tmux server at all), `Enter` spawns a fresh `claude --resume <session-id>` in the session's recorded cwd — new tmux window inside tmux, or new tmux session outside tmux.
- ✓ group-jump keybinds: `J` / `K` jump to the next / previous **project** (lands on the first session of the target group, wraps at the edges, no-op when only one project is on screen). `Ctrl-j` / `Ctrl-k` jump between **hosts** with the same semantics. "More modifiers = bigger jump" — j/k single session, J/K project, ⌃j/⌃k host. Helpers live in `dashboard.rs` and are pure index walkers, so the catalog-vs-rows split stays clean.

### M1 — Session creation + worktree management

- ✓ minimal config: `~/.config/agent-mux/config.toml` with `workspace_folders = [...]`. Tilde expansion; missing file tolerated (empty list).
- ✓ repo registry: depth-1 scan of each workspace folder at startup, identifying real repos (children with `.git/` as a directory). Worktree pointers are excluded so agent-mux-created worktrees don't litter the picker alongside their parent repos.
- ✓ WorktreeManager: `git worktree add -b <slug> <path> <base>` into a hidden sibling of the parent repo (`<repo>/../.agent-mux-worktrees/<repo>-<slug>`); writes `.agent-mux/task.toml` with task / base_branch / created_at. The dot-prefixed parent keeps the workspace folder uncluttered under default `ls` while `git worktree list` and the dashboard's parent-repo grouping (which reads each worktree's `.git` pointer file) report worktrees correctly regardless of layout. `git worktree add` materialises the intermediate `.agent-mux-worktrees/` directory itself, so no separate `mkdir -p` plumbing is needed. Layout changed 2026-05-18 from a plain `<repo>/../<repo>-<slug>` sibling — dogfooding surfaced workspace clutter outweighing the original file-navigation discoverability rationale, which had already been weakened by the dashboard taking over as the primary discovery surface for worktree sessions. Existing worktrees stay at their original path; only newly-created worktrees land in the hidden dir, and git is happy with both shapes because each worktree's admin entry under `<repo>/.git/worktrees/` uses an absolute path either way.
- ✓ default base-branch resolver: `git symbolic-ref --short refs/remotes/origin/HEAD` → fall back to `main`, then `master`, then prompt with no default.
- ✓ new-session modal: press `n`, pick a repo, name a task, confirm/override the base branch (pre-filled from the resolver). Worktree creation runs on a background thread so the UI never blocks; the footer shows "creating worktree for…" while in flight. On success, `claude` launches in a new tmux window via the existing AttachmentDriver, handing the terminal off via SuspendAndRun outside tmux. **Limitation:** the new session does not appear in the dashboard until agent-mux is restarted — visibility wire-up is tracked as a follow-up in TODO.
- ✓ session titles: each row leads with a human-readable title when available, with cwd dimmed alongside. Precedence: `.agent-mux/task.toml`'s `task` field (for agent-mux-created sessions) → Claude Code's `aiTitle` transcript entry (auto-generated after a few messages) → first user message in the transcript (whitespace-collapsed, truncated to 60 chars with `…`) → fallback to cwd-only. Distinguishes multiple sessions sharing a directory even before `aiTitle` lands. User messages whose content is Claude Code's slash-command wrapper (`<local-command-caveat>…</local-command-caveat>` or `<command-name>…</command-name>`) are skipped at the "first user message" stage — same family as the existing `toolUseResult` skip — so a session whose first input was `/clear` or similar falls through to cwd rather than displaying the envelope text.
- ✓ return-to-dashboard hint: footer keybind line ends with a mode-aware `return: prefix+s` (inside tmux — switch-client took the client to the session's window, `prefix+s` lists sessions to switch back) or `return: prefix+d` (outside tmux — agent-mux suspended itself to run `tmux attach` as a subprocess, `prefix+d` detaches it and the TUI resumes).
- ✓ repo registry TTL refresh: opening the new-session picker triggers a re-scan if the cached snapshot is older than 30s, so repos cloned mid-session appear without an agent-mux restart. The depth-1 walk is cheap enough to run synchronously; the cache prevents repeated walks during rapid open/close.
- ✓ live session discovery: the transcript watcher does a single recursive watch on `~/.claude/projects/` instead of per-file watches, so new transcripts (whether agent-mux just spawned them, or `claude` was started externally) surface in the dashboard as soon as their first JSONL line is on disk. New rows append at the tail so the user's current selection is preserved.
- ✓ stale-session filter: transcripts whose recorded `cwd` no longer exists on disk are dropped at discovery time, so deleted worktrees (e.g. cleaned-up claude-squad worktrees) stop cluttering the list with un-attachable entries. Also filters out the legacy "no cwd metadata" case where the fallback decoded-dir-name path doesn't exist.
- ✓ worktree sessions group under parent repo: discovery reads each surviving `project_dir`'s `.git` pointer file (Git's worktree marker — `gitdir: <parent>/.git/worktrees/<id>`) and records the parent repo path on the `Session`. The dashboard groups by `parent_repo.unwrap_or(project_dir)`, so a session in `discord` and one in a `discord-<task>` worktree share one project header instead of fragmenting into per-worktree entries. Sessions keep their actual `project_dir`; only the grouping key changes. Regular checkouts (where `.git` is a directory) and non-git cwds fall through with `parent_repo = None` and continue grouping by `project_dir` as before. The `.git` read piggybacks on the existing bulk-read pipeline — one extra `Host::read_many` round-trip per discovery pass, amortised across all sessions on the host. `parent_repo` is persisted in the per-host session cache (with `#[serde(default)]` for backward-compat with caches written by earlier builds).

### M2 — Remote hosts

- ✓ host config schema: `[hosts.<name>]` tables in `~/.config/agent-mux/config.toml`, each with `ssh = "<target>"` (a `~/.ssh/config` alias or `user@host`) and an optional `transcript_root` (tilde-expanded; defaults to `~/.claude/projects`). The table key is the dashboard label, separate from the SSH destination so the label can stay friendly. `local` is reserved and rejected at load.
- ✓ `Host` trait + `LocalHost`: read-side host abstraction (list transcripts, read a file, tail N bytes, is-dir) wired through discovery and the transcript watcher. Pure `std::fs` for the local impl; the trait is the seam SSH plugs into without disturbing callers.
- ✓ `SshHost`: shells out to the system `ssh` binary, reusing one `ControlMaster` connection per host so each operation is a local-socket round-trip rather than a full TCP+TLS+auth handshake. Drop guard runs `ssh -O exit`; ControlPersist=600 caps stranded masters at 10 min of idle on the remote side if the guard never fires. `ConnectTimeout=5` bounds the startup hang per host. Remote `find -printf '%T@ %p\0'` for transcript listing, `cat` / `tail -c` for reads, `test -d` for is-dir.
- ✓ remote session discovery: each `[hosts.<name>]` in config gets a background thread at startup that opens its `ControlMaster`, runs discovery against the host's `transcript_root`, pre-computes initial attention against the same connection, and posts results back to the dashboard. Local sessions appear immediately; remote sessions stream in as their hosts connect (parallel, not blocking). Connect failures accumulate into a sticky footer line (`connect failed: name1, name2`) so a second failure doesn't silently overwrite the first; the line sits below transient status. Footer shows "connecting to N host(s)…" while pending.
- ✓ remote attention polling: the Transcript Watcher spins up one background polling thread per connected SSH host, ticking every 3s (M5 will make this configurable). Each tick runs `list_transcripts` on the host's existing `ControlMaster` connection, then `tail -c`s only transcripts whose mtime has advanced since the last scan — idle remote sessions cost one `find` per interval, not N tails. Newly-appearing remote transcripts also surface via this loop, producing the same `NewTranscript` events the local recursive `notify` watch does (tagged with the originating `HostId` so the dashboard builds the session through the right `Host` impl). Result: `needs-input` and `working` transitions on remote sessions reach the dashboard live, within one poll interval.
- ✓ remote tmux attach: pressing Enter on a remote session runs `ssh -S <ctrl-socket> <target> tmux list-panes -a` over the host's existing `ControlMaster`, matches `pane_current_path` against the session's `project_dir`, then `ssh -t <target> tmux attach -t <pane>`. When no pane matches (remote tmux crashed, or the session was started outside tmux), the driver falls through to `ssh -t <target> tmux new-session -A -s agent-mux-<id> -c <cwd> claude --resume <id>` — a deterministic per-conversation tmux session name plus `-A` makes the fallback idempotent (a second attach reuses the same session instead of racing a parallel `claude --resume` on the transcript). Inside local tmux this lives in a new local tmux window (nested tmux — see README for the prefix-collision gotcha); outside tmux it `SuspendAndRun`s the ssh as a foreground subprocess so the user lands directly in the remote tmux. Same shape for `t` (spawn-terminal-in-cwd): `ssh -t <target> tmux new-window -c <remote-cwd>`. The host abstraction exposes the ssh argv builder via `Host::ssh_argv(tty, remote_cmd)`, which shell-quote-joins `remote_cmd` into one final argv element — necessary because SSH joins post-target args with spaces and the remote shell re-tokenizes, which (without quoting) breaks `#`-prefixed `-F` format strings and splits `claude --resume <id>` into three tokens. The `AttachmentDriver` builds the actual `Command`, keeping the spawn/attach concerns out of `Host`.
- ✓ dashboard grouping by host then project: sessions render under bold `── local ──` / `── alpenglow ──` host headers (local always first, SSH hosts alphabetical, headers only appear for hosts with ≥1 session), and within each host under dim project headers showing the home-shortened `project_dir`. Projects within a host order by most-recent-session desc; sessions within a project order by recency desc. `j`/`k`/↑/↓ skip past both kinds of headers — selection always lands on a session row. The per-row host and project spans are gone (the headers carry those signals); session rows are indented two levels and show only the attention glyph, title, and age. Title-less sessions fall back to a short session-id suffix so two unnamed sessions in the same project remain distinguishable.
- ✓ remote-session disk cache: after every successful remote discovery, agent-mux writes a per-host snapshot to `~/.cache/agent-mux/sessions/<host>.json` (id, project_dir, transcript_path, last_activity, title, attention). On next startup, those snapshots seed the catalog *before* any `ControlMaster` handshake runs — so configured remote hosts paint immediately instead of popping in over multiple seconds as each SSH connect completes. When the live discovery for a host returns, `SessionCatalog::reconcile_host` drops entries the remote no longer has, overlays fresh attention/title on the rest, and appends anything new; selection re-seats on the same session id so the highlight doesn't jump. Cache writes are atomic (`tmp` + rename) and best-effort — an unwritable cache dir never fails discovery. Missing or corrupt cache files silently degrade to an empty list. Per-host files keep one bad snapshot from poisoning the others; the wire format is a parallel `CachedSession` struct (not serde-on-`Session`) so in-memory fields can evolve without bumping a schema version.
- ✓ discovery recency filter: `discover()` drops transcripts whose `mtime` is older than `DISCOVERY_MAX_AGE` (30 days, hardcoded for now — M5 exposes the knob) at the `list_transcripts` boundary, before any per-session `cat` / `is_dir` / task-toml round-trip runs. Applied to both local and remote so the user's "old session" mental model doesn't shift based on which host the transcript lives on. Tests pin both halves of the cutoff (cold filtered, warm survives) plus the default-constant path so a future flip in comparison direction blows up loudly.
- ✓ bulk discovery: `Host::read_many` and `Host::is_dir_many` collapse what used to be N sequential SSH round-trips inside `build_session` into one batched call per phase. New shape: (1) list transcripts, (2) bulk-read all surviving transcript content in one round-trip, (3) bulk `is_dir` on the unique `project_dir`s, (4) bulk-read `.agent-mux/task.toml` for the ones that exist. Each phase is one ssh subprocess regardless of N. The fetched transcript content is also reused locally to derive initial attention via `derive_attention_from_content`, so the previously-separate `derive_attention` pre-compute loop in `main.rs` is gone — no extra `tail -c` round-trip per session at startup. SSH `Compression=yes` is set on the `ControlMaster` so JSON payloads ride the SSH gzip layer (no help when the proxy already compresses, no harm otherwise). End-to-end measured 2026-05-18 on a coder-proxied remote with 24 surviving sessions (233 → 24 after recency filter, ~16 MB transcript payload): 7+ minutes (pre-recency-filter baseline) → 55 s (recency filter alone) → ~6 s warm / ~15 s cold (this change). The warm/cold split is the remote VM's page cache; the common re-launch case lives in the warm window. Wire protocol for `read_many` is `OK <bytes>\n<bytes>` per existing file and `MISS\n` per missing path, length-prefixed so per-path NotFound surfaces without failing the batch and binary-clean content round-trips without delimiter games. Tests pin both halves of the parser (mixed-record decoding, truncated-content rejection, bad-header rejection) plus the local-impl parity.
- ✓ progressive remote-host registration: `connect_and_discover` now sends `RemoteDiscoveryResult::Connected` the moment the SSH `ControlMaster` is up (~3 s on a coder-proxied host), letting the main thread register the `Arc<dyn Host>` in `App.hosts` and start both the transcript-polling and pane-polling threads — *before* the slower discovery phase finishes. Previously the host wasn't registered until `Ready` arrived with the full discovered `Vec<Session>`, which meant cached remote rows seeded from `~/.cache/agent-mux/sessions/<host>.json` were *visible* in the dashboard but pressing Enter on them silently no-op'd until discovery completed. Now: cached rows are attachable within seconds of launch; discovery's `Ready` event arrives later and overlays fresh sessions via `reconcile_host` without touching the host registration. `Failed` continues to cover both connect-time failure (host never registered) and discovery-time failure (host stays registered, just no fresh overlay this run). The footer's "connecting to N host(s)…" hint stays up until `Ready` so the user can distinguish "the host is ready" from "discovery still running"; `pending_hosts` decrements on `Ready`/`Failed` only.
- ✓ host write-side primitives (`Host::run`, `Host::write_file`): trait surface for the post-M5 remote-session-creation arc. `Host::run(cwd, program, args) -> io::Result<Output>` is the seam `WorktreeManager` and the default-branch resolver will route their `git` calls through. Returns full `std::process::Output` so callers can dispatch on exit code without a one-size-fits-all "non-zero is Err" baked into the trait — `git symbolic-ref` exiting 1 falls back to `main`, whereas `git worktree add` exiting 1 should propagate stderr. `LocalHost` uses `Command::current_dir`; `SshHost` prefixes the shell command line with `cd <quoted cwd> && ` so the *remote* shell handles directory changes, keeping callers host-agnostic. Each token is single-quoted via the existing `shell_join_quoted` so spaces / globs / leading-`#` (the `-F #{format}` case from `ssh_argv`) round-trip verbatim. `Host::write_file(path, content)` is the write-side counterpart to `read_to_string`; `LocalHost` uses `fs::write`, `SshHost` pipes content over `ssh master 'cat > <path>'`. Not atomic — adequate for the `.agent-mux/task.toml` use case where a retry creates a fresh worktree anyway; an atomic `tmp + rename` shape can drop in later behind the same method when a caller needs durability. No callers switched over yet (pure plumbing); next commit in the arc plumbs `Repo.host` + remote workspace scanning.
- ✓ host-aware repo registry + picker: `Repo` gains a `host: HostId` field so the new-session flow knows which host to create the worktree on. `[hosts.<name>]` config gains an optional `workspace_folders` — when omitted, the host inherits the top-level `workspace_folders` (centralised in `HostConfig::effective_workspace_folders` so the fallback isn't sprinkled across call sites). `RepoRegistry::from_config` scans the local host synchronously at startup; a new `RepoRegistry::reconcile_host(host, repos)` method replaces a host's slice without disturbing other hosts' entries, called after a background workspace scan returns. The scan routes through the trait via `scan_host_workspaces(host, folders)` — one `Host::run("find", …)` per folder to list immediate sub-directories, then one `Host::is_dir_many` batch to filter for real `.git/` directories (worktree pointer files still excluded). Same code path serves local and remote. New-session picker shows host-labeled rows (`[gizmo] alpha  /srv/work/alpha`); rows whose host isn't yet in `App.hosts` (cached / pending / failed) render dimmed and selecting them no-ops, matching the M2 attach UX where cached-but-unconnected rows are visible-but-inert.
- ✓ remote worktree creation through `Host::run`: `WorktreeManager::create` now takes `&dyn Host` and routes every `git` invocation through it (`rev-parse --show-toplevel`, `worktree add`, `show-ref` for the branch-exists probe). `resolve_default_base_branch` likewise. The `.agent-mux/task.toml` metadata write goes through `Host::run("mkdir", &["-p", …])` + `Host::write_file` so the dotfile lands on the right side of the SSH tunnel. `LocalHost::run` now strips the `GIT_*` env vars (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_COMMON_DIR`, `GIT_PREFIX`) so the worktree tests survive being run from inside a pre-commit hook that has those set against the surrounding repo; SSH hosts don't need this because ssh login shells start with a fresh env. `App::start_creating` resolves the host from `App.hosts` and hands `Arc<dyn Host>` to the background create thread; submitting a remote-repo selection from the picker now actually creates the worktree on the remote (the step-2 "not yet wired" status message is gone). Default-branch resolution for *remote* repos is still skipped at the modal layer — a synchronous SSH round-trip mid-keypress would block the UI — so remote repos start with an empty branch field and the user types theirs; resolving lazily on background-thread is the next polish step.
- ✓ remote `claude` spawn end-to-end: `AttachmentDriver::spawn_session` takes `&dyn Host` and dispatches on `host.id().is_local()`. Local path is unchanged (`tmux new-window -c <cwd> claude` inside tmux, `tmux new-session -c <cwd> claude` outside). Remote path runs `ssh -t target tmux new-session -c <remote_cwd> claude` via the existing `run_remote_interactive` helper that already serves remote attach + spawn-terminal — same inside-tmux / outside-tmux dispatch, same `ssh_argv` plumbing, same `SuspendAndRun` shape for the outside case. No `-A` flag here (unlike the resume path) because this is the initial spawn — tmux auto-names the session and the dashboard will discover the new transcript on the next remote-poll tick, at which point the user can attach via the normal `Enter` path. `NewSessionResult::Created` now carries the `HostId` alongside the path so `drain_creates` can resolve the right `Arc<dyn Host>` from `App.hosts` and hand it to `spawn_session` — the path alone doesn't disambiguate. Completes the four-commit remote-session-creation arc: `n → pick a remote repo → fill task + branch → submit → worktree + branch + task.toml created on the remote → claude launches in a fresh remote tmux session → transcript surfaces in the dashboard → attach via Enter` all without leaving agent-mux.

### M3 — Inline preview

- ✓ transcript renderer: pure JSONL parser (`src/preview.rs`) that emits an ordered `Vec<PreviewLine>` from a transcript's bytes. Variants: `User(text)`, `Assistant(text)`, `ToolUse { name, summary }`, `ToolResult { ok }`. Filters housekeeping (`ai-title`, `permission-mode`, `file-history-snapshot`, `attachment`, `system`/`local_command`) and sidechain entries so the output reflects the user-visible primary conversation. Tool-call summary is per-tool: Bash uses `description` (falling back to first line of `command`), file tools use `file_path`, search tools use `pattern`, web tools use `url`/`query`, everything else gets an empty summary. Best-effort throughout — malformed JSON lines and unrecognised entry shapes are silently dropped rather than propagated as errors. The renderer carries no UI awareness (no truncation, no styling) so a future Shape B chat surface can consume the same `PreviewLine` stream with a richer renderer.
- ✓ preview pane: `p` toggles a right-side 55/45 split of the dashboard list area. The selected session's recent transcript activity renders in the right pane: bold `> prompt` for user prompts, default-weight `  text` for assistant prose, cyan `⚒ Tool: summary` for tool calls, green `↳ ok` or red `↳ error` for tool results. Lazy-fetched on selection change while the pane is open — one `read_tail(64 KB)` round-trip per session, cached by `SessionId` so navigating back is instant. Cache state doubles as in-flight dedup (`Loading` placeholder blocks duplicate fetches when j/k flutters across the same row). An attention event for a session invalidates its cached preview so the next tick refetches — stale previews are worse than a brief "loading…" because the dashboard can't otherwise tell the user the transcript moved underneath them. Remote sessions use the same `Host::read_tail` path the watcher uses, so SSH previews route over the existing `ControlMaster`. Failed reads render "preview unavailable: …"; the cache holds the failure until something invalidates it (selection re-toggle or attention update), avoiding a per-tick retry storm against a permanently-down host.
- ✓ preview paragraph structure preserved: the parser keeps `\n` separators in user prompts and assistant prose (collapsing only intra-line runs of spaces/tabs and stripping outer blank lines), and the renderer expands each entry into one `ratatui::Line` per paragraph with a continuation indent aligning under the first-line content. Cap of 6 visual lines per entry — a 7th line becomes `…` so a long assistant reply can't crowd out more recent activity. Replaces the prior "everything-on-one-wrapped-line" rendering that was unreadable on multi-paragraph answers.
- ✓ preview pane fits the terminal height: the parser keeps up to 100 source entries (`PREVIEW_LIMIT`, raised from 20) and the renderer trims composed visual lines from the **top** at draw time to fit the pane's inner height. The newest entry stays pinned to the bottom of the pane regardless of terminal size — tall terminals naturally fill with more entries; short terminals never hide the most recent activity. Mid-entry trims are allowed and read like scroll.
- ✓ preview readability — DIM modifier removed: assistant prose previously carried `Modifier::DIM`, which rendered as unreadable-faint on several common terminal palettes. The default style is now the terminal's normal foreground; user prompts still pop via bold, tool lines via per-theme colour. Users who want a quieter assistant can set `assistant_fg = "bright_black"` (or similar) in `[theme]`.

### M4 — Attention notifications

- ✓ OS-level notification on transition into `NeedsInput`: when the catalog moves a session's attention from `Working`/`Idle`/`Unknown` to `NeedsInput`, the `Notifier` fires one notification via `notify-rust` (libnotify on Linux, NSUserNotification on macOS). Payload: title `agent-mux: <session title>` (falls back to a short session-id suffix when title is unresolved), body `<host> · <project>`. Dispatch happens on a fire-and-forget thread so a slow D-Bus reply can't back-pressure the UI thread; a missing notification daemon surfaces as a silent no-op (dogfood feedback, not a crash). Wired at the catalog's `update_attention` boundary — the catalog returns the previous attention so the notifier sees a true transition signal, not just a poll-cadence re-derivation of the same state.
- ✓ in-process suppression: two layers per session. (1) Episodic flag — set on dispatch, cleared only when the session leaves `NeedsInput`. One ping per "the assistant just stopped" event; ignoring the notification while the session sits in `NeedsInput` does not produce a second ping. (2) Time-window debounce — `DEBOUNCE_WINDOW = 5s` suppresses re-fires for the same session even when the episodic flag would otherwise allow them. Catches Working↔NeedsInput flapping at the watcher's poll cadence without muting genuine consecutive episodes more than a few seconds apart. Failed dispatch does *not* arm the suppression — a transient libnotify outage stays self-healing.

### M5 — Customization

- ✓ `[notifications]` config section: `enabled` (master toggle, default `true`), `sound` (request the OS default notification sound, default `false` — preserves pre-M5 silent behaviour), `disabled_hosts` (per-host suppression by `[hosts.<name>]` label, default empty). Read at startup into `NotificationsConfig`; `Notifier::update_config` hot-swaps the live config so the M5 reload-on-edit work (still pending) can re-apply without a restart. Leaving-`NeedsInput` bookkeeping runs even while the master toggle is off so re-enabling later doesn't see a stale "still in episode" flag. The dispatcher plumbs `sound` through `Payload` and conditionally calls `notify-rust`'s `sound_name("default")` — picking specific sound files is a post-M5 follow-up.
- ✓ `[theme]` config section: per-element colour overrides for the four attention-glyph states (`needs_input`, `working`, `idle`, `unknown`), three preview line types (`tool_use`, `tool_result_ok`, `tool_result_err`), and the two preview-chat fields (`user_fg`, `assistant_fg` — default unset, so the terminal foreground is used; provided as the knob for users who want a custom colour after the hardcoded DIM was removed). Each value is a string: named ANSI colour (`red`, `cyan`, …), `bright_*` variants (`bright_red`), or `#RRGGBB` hex. Empty string or `"default"` falls back to the terminal default with no `fg` set. Unknown colour names fail loudly at config load with the offending field name in the error — silent fallback would mask a typo. Parsing happens once on startup; the resolved `Theme` is a `Copy` struct of `Option<Color>` so render paths never re-parse strings. The attention glyph now picks up its theme colour via a small `apply_fg` helper that stays a no-op when the user hasn't themed that element.
- ✓ theme presets: a `preset` field in `[theme]` selects a named built-in palette that the per-element fields then overlay. Ships with `"default"` (pre-M5 scheme, attention glyphs uncoloured), `"bright"` (high-contrast — every attention state coloured, preview uses `bright_*` variants), `"mono"` (no foreground colours at all; structural modifiers like bold/dim still carry the visual distinctions), `"warm"` (sunset reds/ambers/earthy browns), `"cool"` (ocean blues/teals/sea greens; errors stay rose so the attention signal still pops against the cool surround), `"solarized"` (canonical Solarized accents — works over either the dark or light Solarized backgrounds since agent-mux doesn't set a background), `"gruvbox"` (Gruvbox bright variants, earthy retro feel), and `"nord"` (Nord aurora + frost; polar-night slate tones with aurora reds/yellows/greens for events). User-set fields take precedence over the preset's value; un-set fields inherit. An explicit empty-string override clears one preset entry without affecting siblings. Unknown preset name fails loudly at load with the list of available presets in the error. The "default" preset is also what an empty `[theme]` section resolves to, so existing configs render identically.

- ✓ CLI subcommands for discoverability: `agent-mux themes` prints every built-in preset with each colourable element rendered in its actual colour (truecolor `\x1b[38;2;…m` escapes for `Color::Rgb`, named `\x1b[3Nm`/`\x1b[9Nm` for ANSI variants) plus the colour's canonical label so the user can pick a palette by sight before editing the config. `agent-mux config` opens with a "Current configuration" block (which candidate path was loaded, the parsed `workspace_folders` / `hosts` / `notifications` / theme — or the searched-paths list when nothing existed, or the parser error when the file was malformed) and then prints a self-contained TOML reference documenting every key with its default and a one-line description — copy-paste straight into `~/.config/agent-mux/config.toml`. The status block is the diagnostic for "agent-mux isn't seeing my config" without log-spelunking. `agent-mux help` / `--help` lists the subcommands. ANSI escapes are emitted only when stdout is a terminal (via `IsTerminal`), so piping into a non-`-R` pager or a file yields plain text. Unknown subcommand exits with code 2 and prints the help to stderr.

- ✓ Config path resolution honours XDG on macOS: `Config::load` now walks a precedence list (`$XDG_CONFIG_HOME/agent-mux/config.toml`, then `~/.config/agent-mux/config.toml`, then `dirs::config_dir()/agent-mux/config.toml`) and reads the first one that exists. Before, macOS users got `~/Library/Application Support/agent-mux/config.toml` from `dirs::config_dir()` even though every doc, error message, and CLI helper named `~/.config/agent-mux/config.toml` — the documented path silently didn't load. The platform-native location is still searched as a final fallback so anyone already on it isn't disturbed. The candidate list is exposed (`config::config_search_paths`) and fed into `agent-mux config`'s status block so a "no config file found" run names every path that was checked.

### Packaging

- ✓ nix flake: top-level `flake.nix` exposes `packages.<system>.default` (a `rustPlatform.buildRustPackage` over `Cargo.lock`), `apps.<system>.default`, `devShells.<system>.default` (cargo + rustc + clippy + rustfmt + rust-analyzer), and `overlays.default` so consumers can drop `agent-mux` into their `pkgs`. Cross-platform via `flake-utils.eachDefaultSystem` — covers the four common nix systems (`x86_64-linux`, `aarch64-linux`, `x86_64-darwin`, `aarch64-darwin`). Pinning is the consumer's `flake.lock` — `latest`-the-tag staying mutable doesn't matter on this path because the flake input resolves to a commit SHA. Runtime tools (`tmux`, `ssh`, `git`, `claude`) deliberately not in the closure — system-tool dependencies, supplied from the consumer's environment. `doCheck = false` because the test suite shells out to `git`/`ssh` and assumes a real environment (host::tests pin ControlMaster lifecycle); release.yml's release build doesn't run tests either, so the flake matches that split — testing is `check.yml`'s job, the flake just produces a binary. devShell's `shellHook` unsets `DEVELOPER_DIR` on macOS so Apple's `/usr/bin/python3` stub falls back to Command Line Tools instead of the nix-bundled Apple SDK (which has no python3); without this, any python script invoked from a subprocess agent-mux spawns — e.g. the Coder CLI used as a `ProxyCommand` for `*.coder` SSH targets — dies with "tool 'python3' not found" and the remote-host connect exits 255. nix's cc-wrapper has its header paths baked into `NIX_CFLAGS_COMPILE`, so cargo builds (including objc2-* and Cocoa-framework crates) still link cleanly without `DEVELOPER_DIR`. No-op on Linux.

### Post-M5 — embedded-PTY dashboard (Shape B pivot)

The dashboard arc that took agent-mux from "switch-client to a tmux window" to "host a tmux window *inside* the dashboard" — the Shape B transition the `AttachmentDriver` trait was put there to allow. Six standalone phases, each landed as its own commit. The default attach experience changed 2026-05-18; `--no-embed` opts back into the legacy flow for one release.

- ✓ standalone `embedded_pty` module: spawn `argv` into a pty (`portable-pty`), read on a background `std::thread` into a shared `vt100::Parser`, render via `tui_term::PseudoTerminal`, resize the grid, write input bytes. Reader thread is detached so a child that ignores SIGHUP can't stall app shutdown (same shape as the SshHost polling threads). 10 unit tests cover spawn/exit/resize/input-via-pty-echo.
- ✓ `PtyDriver` `AttachmentDriver` impl: emits a new `AttachOutcome::EmbedPty(spec)` variant carrying the argv the embedded widget will spawn. Same try-pane-then-resume dispatch as `TmuxDriver`; the difference is the outcome variant and the fact that PtyDriver always uses the named-`-A` resume form so re-attaches converge. Shared `tmux_attach_argv` / `tmux_resume_argv` helpers consolidate tmux command strings between the two drivers — a future tmux-flag change lands in one place.
- ✓ `Focus` state machine + main-loop wiring: new `Focus::{Sidebar, Terminal{leader_armed}}` enum on `App` routes input. Sidebar focus keeps the legacy keybinds; Terminal focus forwards every key to the PTY via `encode_key_for_pty` (chars + Ctrl/Alt modifiers, Enter/Tab/Backspace/Esc, arrows, navigation keys, F1–F4). `Ctrl-a Esc` is the only intercepted chord — modelled on tmux's prefix convention, picked to avoid collision with tmux's own `Ctrl-b` when nested. Same-session re-attach is a fast path (no respawn); different-session attach drops the old PTY and spawns a new one. Compact ~40-col sidebar layout replaces the preview pane when attached. Footer collapses to `⌃a esc: back to sidebar` while terminal-focused. Main-loop tick drops from 100 ms (sidebar) to 16 ms (terminal) so PTY output renders snappily.
- ✓ resize cascade: each frame compares the rendered area against `Embedded.last_size` and fires `EmbeddedPty::resize` only on change — sending SIGWINCH on every frame would be 60 wakeups/sec for nothing. Zero-sized areas (terminal shrunk past the borders) are rejected so vt100 doesn't see a zero dimension.
- ✓ mouse forwarding + bracketed paste: `EnableMouseCapture` + `EnableBracketedPaste` enabled at terminal-setup time only when `--embedded` is in effect (non-embedded runs preserve native mouse text-selection). Crossterm mouse events translate from terminal-absolute to PTY-relative coordinates and forward as SGR (xterm 1006) reports — Down/Up/Drag (all three buttons), Scroll{Up,Down}, modifier bits. Paste events wrap in `\e[200~ … \e[201~` with the close-marker stripped from the payload (paste-injection mitigation). Clicks outside the embedded pane are dropped.
- ✓ default flip: `PtyDriver` becomes the default driver; `--no-embed` opts back into the legacy `tmux switch-client` / `SuspendAndRun` path. `--embedded` is silently accepted (no-op) for one release so users who aliased it during the dogfood phase don't see breakage. SPEC.md / ARCHITECTURE.md / README.md updated to describe embedded mode as the default; the TODO entry tracking the arc is deleted.

### Cross-cutting polish

- ✓ session search / filter: `/` opens a search bar in the dashboard that live-filters the session list by case-insensitive substring against title, `project_dir`, and host label — the three things the user reads when scanning. Two modes: Editing (the bar owns the keyboard, characters append to the query, list filters as you type, ⏎ applies, esc cancels) and Active (filter persists but `j/k/⏎/n/t` work normally; `/` returns to Editing with the existing query, esc clears the filter entirely). Selection re-seats on every keystroke so the previously-selected session stays highlighted if it survives the filter, or falls back to the first matching row. Headers collapse when none of their sessions match — `── alpenglow ──` disappears entirely if no remote sessions match, and a project header drops out when all its sessions are filtered out. The list block title swaps from `sessions (N)` to `sessions (visible/N)` while a filter is active so the user knows whether their query narrowed the list before pressing ⏎. Ctrl-C still quits unconditionally even when the search bar has focus.
- ✓ custom tool keybinds: `[[tools]]` entries in `~/.config/agent-mux/config.toml` add user-defined sidebar keybinds that launch a terminal tool in the selected session's cwd. Each entry is `{ key: <single char>, name?: <label>, command: [<program>, <args>...] }`. The `t: terminal` action is the degenerate case (no command — drops into a shell); custom tools route through the same attachment-driver plumbing (`spawn_tool`), so inside tmux they open a new window in cwd and outside tmux they suspend the TUI and run as a foreground subprocess. `{cwd}` and `{host}` tokens in `command` arguments are substituted at fire time against the selected session. Validation at load: single-char `key`, non-empty `command`, no duplicate tool keys, and no collision with built-in dashboard keys (`q j k J K t n / p d` — kept in a `RESERVED_KEY_CHARS` constant alongside `action_for` so a config that tries to override `q` gets a loud error rather than silent shadowing). Works for remote sessions via the same `ssh -t … tmux new-window …` plumbing the existing `t` action uses. `#config #worktree`
- ✓ delete worktree from the dashboard: `d` on a worktree-backed session opens a confirmation modal showing the task / path / host plus a `[ ] force` toggle (`f` to flip). Enter dispatches `git worktree remove` on a background thread via `WorktreeManager::remove` (host-agnostic through `Host::run` — works for local and SSH-reachable worktrees), removes the session from the catalog on success so the row vanishes immediately, and drops the embedded PTY + returns focus to the sidebar if the deleted session was the one being viewed. Pre-cleans `<worktree>/.agent-mux/` before invoking git so the untracked task-metadata file we write at create-time doesn't make every worktree look perpetually dirty — git's safety check only trips on actual user work, which the user then re-runs with the force toggle on. Branch is left alone, transcript is left alone, the remote `agent-mux-<id>` tmux session (if any) is left alone — all three are the user's call to clean up. Sessions whose `project_dir` isn't a worktree (no `parent_repo`) surface a `not a worktree` status line instead of a modal. `#worktree`
- ✓ live tmux-pane indicator: each session row dims its title when no live tmux pane matches the session's `project_dir` — signalling that Enter will fall through to `claude --resume` (multi-second spin-up of tmux + claude) rather than a fast `switch-client` into an existing pane. Mechanism: per-host pane poller spun up alongside the existing transcript watcher (one thread for local, one per connected SSH host) ticks every 3s, runs `tmux list-panes -a -F '#{pane_current_path}'` locally or over each host's `ControlMaster`, sends a `WatcherEvent::LivePanes { host, cwds }` snapshot, and the catalog sets `has_live_pane: Some(bool)` on every session whose `host` matches. Failures (no tmux server, ssh hiccup) surface as an empty `cwds` list — every session on the host transitions to `Some(false)`, matching the user-visible reality. Sessions whose host has not yet reported (initial state, polling thread still spinning up) render at normal weight so a remote whose first poll is in flight doesn't flash dim then bright. The first tick fires immediately so first paint reflects real state. Race against pane death between indicator and Enter is fine: the existing auto-resume fallback handles a stale "live pane" claim gracefully — the indicator is a hint, not a contract.
- ✓ undimmed footer (2026-05-19 dogfood): the footer's status messages and key hints previously rode `Modifier::DIM`, which dogfooding showed was hard to read in practice — the line is informational and the user actually scans it. Status and keybinds share one footer line (status takes precedence when both would otherwise appear), so dropping the dim modifier covers both treatments at once. The broader theme-modifier-override knob under Configuration remains future work; this is the hardcoded fix.
- ✓ new-session picker pre-selects cursor's host/project (2026-05-19 dogfood): pressing `n` from a focused session row now seeds the picker so the cursor lands on the same repo (or at least the same host) rather than always opening at index 0. Implementation: `App::open_new_session` reads the selected session's `HostId` and `parent_repo`-or-`project_dir`, hands it to the modal as `NewSessionSeed`; the modal does an exact host + path match first, falls back to host-only, then to index 0 if nothing matches. Cheap (one linear scan per open) and removes a small but constant per-`n` friction.
- ✓ new-session attach lands in the embedded pane (2026-05-19 dogfood): `PtyDriver::spawn_session` no longer delegates to `TmuxDriver` — it now spawns claude into a detached tmux session (`tmux new-session -d -P -F '#{session_name}' -c <cwd> claude`) and returns an `EmbedPty` that attaches the dashboard's embedded pane to that session. Letting tmux pick the session name guarantees no collision with the user's existing sessions. `drain_creates` synthesises a `SessionId` from the worktree path so `install_embedded` has a key during the brief window before discovery surfaces the real id. Remote symmetry: the same shape over ssh — one round-trip to spawn detached, one ssh+tmux-attach embed. The user now sees claude paint into the right pane immediately rather than getting a jarring fullscreen handoff that broke the post-M5 "sidebar stays visible" contract.
- ✓ no-worktree new-session keybind (2026-05-19 dogfood): `N` (Shift+n) opens the same picker as `n` but in `ModalMode::NoWorktree` — picking a repo immediately spawns claude in the repo root rather than running `git worktree add` first. No task name, no base branch, no `.agent-mux/task.toml`. The modal title swaps to `new session (no worktree): pick a repo` so the mode is visible. Reuses the existing create-channel pipeline (`drain_creates`) by pushing a synthetic `Created { host_id, path: repo.path }` directly — no background work to surface, no `creating` footer state. Works for both local and remote repos through the same `spawn_session` path that worktree-backed sessions use. `N` joins `RESERVED_KEY_CHARS` so user-configured `[[tools]]` bindings can't shadow it.
- ✓ top-level `workspace_folders` rejects tildes (2026-05-19 dogfood): top-level entries used to be tilde-expanded against the local user's home at config load — fine for local-only setups but silently broken for the inherit-to-remote case where the same absolute path got shipped to a remote box that uses a different username. Now `Config::load_from` errors loudly with a directive ("use an absolute path, or move the entry under [hosts.<name>].workspace_folders"). Per-host `workspace_folders` still accept tildes — they pass through to the remote shell which expands them against the remote user's home, the documented and correct behaviour for that section. One rule per section, both unambiguous; no path-rewriting heuristics needed.
- ✓ empty-scan footer hint (2026-05-19 dogfood): when a remote workspace scan completes with zero repos, the footer now surfaces a sticky line — single-host as `alpenglow: no repos in /home/gizmo/workspace`, multi-host as `no repos found: alpenglow, beta`. Slot sits one tier below `connect failed:` in the precedence ladder (a host that connected-but-empty is less severe than one that didn't connect at all). The signal was the diagnostic gap that made the inherit-to-remote tilde bug so hard to find; before this, a configured-but-broken remote path was indistinguishable from "host still connecting." Subsequent non-empty scans clear the warning for that host.
- ✓ config reference moved from `agent-mux config` to `agent-mux help` (2026-05-20 dogfood): the long TOML skeleton printed by `config` was burying the live-parsed status (the actual diagnostic value of the subcommand — "did you read my file?"). Reference is now a one-screen compact form at the bottom of `agent-mux help`: every section, the theme field list, the preset names, the [[tools]] shape — but rendered as descriptive lines rather than a copy-paste TOML skeleton. `config` is now status-only.
- ✓ `agent-mux themes` renders as a table (2026-05-20 dogfood): replaced the per-preset block layout (8 presets × 7 element rows ≈ 90 lines) with a single grid — rows are presets, columns are elements (`● needs_input`, `◐ working`, …). Each cell is the colour name the user would write in `config.toml`, rendered in that colour when stdout is a TTY. Uncoloured cells show an em-dash to flag "no override" without occupying the wide "(terminal default)" phrase the old layout used. Column widths are computed at render time off the actual values, so a future preset with a longer colour string can't silently truncate. Output is now ~22 lines.
- ✓ fix(attachment): remote `t` and `[[tools]]` no longer fire-and-forget into the void (2026-05-20 dogfood): pressing `t` (terminal) or a custom tool keybind on a *remote* session used to send `tmux new-window -c <cwd>` *to the remote tmux server* — which landed the new window in whatever session was "current" on the remote (not necessarily the one the user was attached to), while the *local* wrapper window died immediately because the ssh command (`tmux new-window`) returned 0 the moment the remote tmux took it. Net effect: a dead local window plus an invisible remote window. Now: both remote spawn paths ssh into the host with `sh -c 'cd <cwd> && exec <shell-or-tool>'`. The local window (or `SuspendAndRun` subprocess) hosts the remote shell or tool directly and stays alive until the user exits it — the same shape local-in-tmux already had. Paths with spaces survive both quoting layers; new regression tests pin the wire shape against future drift.
- ✓ `t` and `[[tools]]` open in the embedded pane (2026-05-20 dogfood): `PtyDriver::spawn_terminal` and `spawn_tool` used to delegate to `TmuxDriver` (sibling local tmux window — which dogfooding confirmed was effectively a fullscreen handoff because tmux switched the local terminal to the new window and the dashboard view disappeared). Now both methods emit `EmbedPty` for both local and remote, so pressing `t` or a `[[tools]]` keybind swaps the embedded pane to a shell/tool at the session's cwd. Sidebar stays visible; pressing Enter on the session row swaps back to the claude attach. Synthetic SessionIds (`agent-mux-terminal:<sid>`, `agent-mux-tool:<idx>:<sid>`) key the pane swap so the same keybind refocuses an existing pane while different keybinds cycle freely. The whole "embedded pane is the single 'doing stuff' area" mental model now applies to every action — `Enter`, `n`, `N`, `t`, and tools all land there.
- ✓ focused-pane border indicator (2026-05-20 dogfood): in embed mode the sidebar and the embedded terminal each carry a focus-aware outer border — the focused side renders cyan + BOLD, the unfocused side stays DIM. Replaces the prior BOLD-vs-DIM-only treatment that dogfooding showed was too subtle to spot at a glance, so users no longer mis-target keystrokes (stray edits into the inner PTY, or dashboard commands swallowed by Claude's composer). Outside embed mode the sidebar's border stays plain because there's no rival pane to disambiguate against. Border colour is hardcoded to cyan for now; a `[theme.focus_border]` knob is filed under the broader `[theme]` schema extension in TODO.
